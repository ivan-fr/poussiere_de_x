\begin{abstract}
We describe the engine \texttt{113\_pandrosion\_autonomous\_heuristic\_thales\_engine.py}, an autonomous extractor of complex roots for dense polynomial systems. The engine does not follow every Bezout path. Instead, it builds a single geometric flow combining a Thales-type homothety, a Riemann-Mobius map, optimization of the starting point, and then local correction in the transformed coordinates. The central idea is to shift the numerical effort from homotopic enumeration to initialization geometry. On the Kostlan systems tested, the engine recovers all requested roots for \(ks(2,12)\) and \(ks(2,14)\), namely \(144/144\) and \(196/196\) distinct numerical roots respectively, below the residual threshold used. The document formalizes the flow, clarifies the non-derivative-free nature of 113's local corrector, and reports the reproducible results observed.
\end{abstract}

\section{Problem}
Let
\[
  F=(F_1,\ldots,F_n):\mathbb C^n\to\mathbb C^n
\]
be a polynomial system. For a generic dense system in which each equation has total degree \(d\), the Bezout number is \(d^n\). A complete homotopy strategy typically associates one path with each expected solution. For cases such as \(ks(6,16)\), this gives
\[
  16^6 = 16\,777\,216
\]
theoretical paths. Engine 113 takes another viewpoint: extract useful and distinct roots by direct geometric exploration, without exhaustive path enumeration.

\section{Kostlan systems used}
The tests employ a dense Kostlan-type family. For \(n\) variables and degree \(d\), one considers monomials
\[
  z^\alpha = z_1^{\alpha_1}\cdots z_n^{\alpha_n},\qquad |\alpha|\le d,
\]
and random complex coefficients weighted by multinomial factors. In the script's outputs, the number of terms per polynomial is
\[
  \binom{n+d}{n}.
\]
For example, \(ks(2,14)\) contains \(120\) terms per polynomial, hence \(240\) terms total for two equations.

\section{Single geometric flow}
Engine 113 generates an initial point not directly in the original space \(z\), but in an auxiliary coordinate \(u\). For each coordinate, it applies a Mobius transformation coupled with a homothety:
\begin{equation}
  y_j
  = \Lambda\, p_j\,
    \frac{\cos(\theta_j)(u_j/p_j)+\sin(\theta_j)}
         {-\sin(\theta_j)(u_j/p_j)+\cos(\theta_j)}.
  \label{eq:mobius113}
\end{equation}
Then,
\begin{equation}
  z = A y,
  \label{eq:linear113}
\end{equation}
where \(A\) is a diagonal or quasi-diagonal linear transformation built inside the autonomous engine.

This formula contains several regimes without creating a separate algorithmic branch:
\[
\begin{array}{lll}
\theta_j=0 & \Rightarrow & \text{affine homothetic map},\\
\theta_j\approx \pi/2 & \Rightarrow & \text{inversion regime / map toward infinity},\\
\Lambda\gg 1 & \Rightarrow & \text{strong Thales-type homothety}.
\end{array}
\]
The goal is not only to normalize the variables, but to produce points lying in varied numerical basins.

\section{Starting-point optimization}
The engine applies a \emph{startopt} step. We set
\[
  G(y)=F(Ay).
\]
Starting from the raw point \(y_0\) provided by \eqref{eq:mobius113}, we test a small set of radial and directional perturbations, then keep the candidate that minimizes a starting energy of the form
\begin{equation}
  E(y)=\log(1+\|G(y)\|)+\varepsilon\log(1+\|y\|),
  \label{eq:startopt113}
\end{equation}
with \(\varepsilon\) very small. Geometrically, this step amounts to choosing a better starting point in order to reduce the number of successive proportional constructions needed for correction.

\section{Local corrector of 113}
It is important to characterize the nature of engine 113 correctly. After the geometric flow, the local corrector solves
\begin{equation}
  J_G(y)\Delta=-G(y),
  \qquad y\leftarrow y+\lambda\Delta,
  \label{eq:newton113}
\end{equation}
where
\begin{equation}
  J_G(y)=J_F(Ay)A.
\end{equation}
The scalar \(\lambda\) is chosen by a damped proportional search.

\begin{remark}
Engine 113 is therefore not derivative-free. Its global geometry is Pandrosion/Thales, but its local corrector uses a Jacobian. The engine, however, makes no use of a hidden root solver: it uses neither \texttt{numpy.roots}, nor \texttt{scipy}, nor \texttt{sympy}, nor any external homotopy. The linear solver \(\texttt{np.linalg.solve}\) is used solely to solve \eqref{eq:newton113}.
\end{remark}

\section{Heuristic mechanism}
Engine 113 deliberately stays simple. At each trial, it picks parameters
\[
  (\Lambda,\theta,p,r)
\]
from a deterministic grid and a heuristic pressure tied to duplications and failures. When duplications appear, the homothetic power is pushed toward other scales. This rule can be seen as a discrete version of a basin-of-attraction exploration:
\[
  \text{frequent duplicates} \quad\Rightarrow\quad \text{change scale or map}.
\]
The strategy is unique: it is not a collection of competing policies.

\section{Algorithm}
\noindent\textbf{Input:} a system \(F:\mathbb C^n\to\mathbb C^n\), a target count \(N\), a maximum number of trials \(P\).\\
\textbf{Output:} a set \(R\) of distinct numerical roots.
\begin{enumerate}
  \item Build the dense system and the evaluator \(F,J_F\).
  \item Initialize \(R=\varnothing\).
  \item For \(t=0,\ldots,P-1\):
  \begin{enumerate}
    \item generate a direction \(u_t\), a homothety \(\Lambda_t\), an angle \(\theta_t\), and a pole \(p_t\);
    \item apply the flow \eqref{eq:mobius113}-\eqref{eq:linear113};
    \item optimize the starting point via \eqref{eq:startopt113};
    \item correct via \eqref{eq:newton113};
    \item validate the residual \(\|F(z)\|\) and add the root if it is distinct.
  \end{enumerate}
  \item Stop when \(|R|=N\) or when the trial budget is exhausted.
\end{enumerate}

\section{Discussion}
The main interest of 113 is to show that strong geometrization of the initialization can replace, for the extraction of many roots, the systematic tracking of Bezout paths. The success on \(ks(2,12)\) and \(ks(2,14)\) is particularly noteworthy because the algorithm does not explicitly construct the \(d^n\) starting paths. On the other hand, 113 remains locally an engine with derivatives. To obtain a version more faithful to the pure Pandrosion idea, one must replace \(J_G\) with an exact slope matrix \(Q(a,b)\). This is precisely the subject of engine 115.

\section{Reproducibility}
Commands used for the main cases:
\begin{verbatim}
python -S 113_pandrosion_autonomous_heuristic_thales_engine.py \
  --cases 2,12 --equation-normalize --count 144 --pool 5000 \
  --epochs 24 --accept 1e-8 --cluster-sep 1e-8 \
  --startopt-candidates 12

python -S 113_pandrosion_autonomous_heuristic_thales_engine.py \
  --cases 2,14 --equation-normalize --count 196 --pool 7000 \
  --epochs 24 --accept 1e-8 --cluster-sep 1e-8 \
  --startopt-candidates 12
\end{verbatim}

\section{Conclusion}
Engine 113 proposes an autonomous, multivariate scheme with no dependency on older scripts. Its contribution is the single geometric flow combining strong homothety, Riemann-Mobius maps, and starting-point optimization. This global layer makes the local correction very efficient on the Kostlan benchmarks tested. Its mathematical limitation is clear: the local corrector is of Jacobian type. This limitation naturally motivates a pure Pandrosion version based on an exact slope matrix.
